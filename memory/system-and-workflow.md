## 저장소 역할 분담

| 저장소 | 역할 | Claude 접근 방법 |
|--------|------|----------------|
| 이 git 저장소 `memory/` | 맥락 허브 (HISTORY, index, 이 파일, method, tools, preferences) | 파일 직접 읽기/쓰기 + 커밋 |
| 이 git 저장소 `knowledge/` | 매매 가이드·교육 자료 | 파일 읽기 |
| Notion | 상세 데이터, 표, 라운드 상세, 계좌 성적 | Notion MCP (fetch / update-page) — Claude Code에서 커넥터 연결 필요 |

*(기존 GitHub MyAssetDashBD 저장소는 대시보드 코드용으로 별개. 트레이딩 기록과 섞지 않는다.)*

## 세션 초기화 프로토콜

> 새 대화 시작 시 이 순서로 맥락 복원. 사용자 요청 없이 자동 수행.

1. **HISTORY.md 🔔 항목 확인** — 미결 항목 있으면 사용자에게 먼저 제시
2. **index.md 자원 지도 파악** — 이번 세션 필요 자원 위치 확인
3. **사용자 제공 자료 수신** — 키움 캡쳐 / Firebase JSON (없으면 요청하지 않고 대기)
4. **Notion 페이지 fetch** — 필요한 경우에만 (Discord 체크, 라운드 상세, 계좌 성적 등)
5. **사용자에게 브리핑** — 현재 상태 요약 + 미결 항목 제시

## Notion 업데이트 패턴

**장 중 세션 (09:00~15:30)**: Notion 기록 금지. 매매 논의·판단에만 집중.
**장 종료 후 또는 장 전 (전일 정리 맥락)**: 그때 확정된 수치로 한 번에 기록.

| 작업 | 방법 |
|------|------|
| 라운드 진행 중 상태 갱신 | 장 종료 후(또는 익일 장 전)에만 update-page — 장 중 캡쳐·지침을 받아도 Notion 갱신 안 함 |
| 라운드 종료 시 | "오빌계좌 성적" 또는 "일반비중매매 계좌 성적" 이력 표에 종료일·실현손익·수익률 기재 |
| 새 라운드 페이지 생성 | 최상위 페이지 하위에 생성, index.md 진행 중 항목 업데이트 |
| Discord 체크 요청 | "일반매매 Discord 체크포인트 관리 가이드" 참고 → 해당 종목 페이지 확인 (읽기만, 쓰기는 장 후) |

## 상쇄매도 쌍 (계좌별 — 혼동 금지)

| 계좌 | 수익 종목 | 손실(상쇄) 종목 | 규칙 |
|------|----------|---------------|------|
| 연습/일반매매 계좌 | 성호전자(현재) | **남성** | 동일 계좌 내 쌍으로만 진행 |
| 오빌계좌 | 우리기술(현재) | **알에프텍** | 동일 계좌 내 쌍으로만 진행 |

→ 남성 상쇄매도 시 오빌계좌 알에프텍 수치 참조 금지. 각 쌍은 각자 계좌 안에서만.

## 코드 작업

이 저장소에는 코드가 없다. 대시보드 코드(MyAssetDashBD)가 필요한 작업은 해당 저장소에서 진행하며, 변경 전 계획·보고 → 승인 후 구현 규칙은 그 저장소의 CLAUDE.md를 따른다. (과거 claude.ai에서는 코드작업지시서를 작성해 Claude Code에 위임하는 방식이었음. `specs/OBIL_TRACER_작업지시서.md`는 MyAssetDashBD 용 지시서 보관본이다.)
